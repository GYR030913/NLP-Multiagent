# M3 记忆管理逻辑与操作说明

本文描述当前实现，不把规划中的向量检索、自动演进或实验收益当作已有能力。入口代码是 `collab/memory.py`、`collab/working_set.py`、`collab/context.py`、`collab/engine.py`。研究和数据版本分别由 `collab/research.py`、`collab/data.py` 管理。

## 1. 三类信息各负什么责任

**原始证据**保存“实际发生了什么”：人工消息、任务版本、工具输入/结果、实际审查、来源正文快照、数据集快照和不可变产物。事件序号、文件 SHA256、bundle ID、source ID 和 dataset ID 用于定位它们。工作集或模型写出的结论不能替代这些证据。

**短期工作集**保存“当前任务要记住什么”：目标、验收条件及 revision、人工约束、依赖与输入版本、待处理人工请求、最近证据引用、待验证假设和未解决问题。短期指当前任务的用途；它写入 `state.json`，退出程序后不会消失。

**长期记忆**保存“之后可能复用什么”：一次失败的情节、程序性经验、有范围/日期的事实与接口、已经确认的偏好。正文应是简短事实或建议，不复制完整代码、论文或网页，不保存隐式推理链和密钥。模型反思最初只是候选。

原始对话继续保留。任务二在同一群组继承任务一的公开产物、公开约束以及有权限检索的记忆；不会通过复制其他角色的私有工作目录来继承知识。

## 2. 存储位置与可信边界

每个群组独立保存以下内容：

- `state.json`：任务、事件、请求、工作集、记忆 outbox、来源读取范围和数据登记元数据。
- `memory-v2/events.jsonl`：长期记忆的追加日志；保存内容版本和状态变化，是长期记忆的权威记录。
- `memory-v2/index.sqlite3`：可删除、可重建的派生索引。当前检索采用确定性关键词，不依赖 FTS5、向量数据库或外部 embedding。
- `agents/<role>/memory.jsonl`：旧版日志；保留兼容和恢复用途，新引擎生成的反思进入 v2 日志。
- `sources/<sha256>`、`datasets/<sha256>`、`artifacts/<sha256>`：完整正文、数据快照和交付文件。记忆用 ID 引用它们。

控制面目录没有挂载给生成代码。`code.run` 只看到当前角色/私有任务的 workspace。记忆工具没有任意路径参数；Agent 不能通过记忆接口读写 `state.json` 或其他角色目录。

同一群组的写操作继续由 `writer.lock` 串行保护。当前实现不提供多个写进程并发提交，也不把四个角色称为四路并行执行。

## 3. 短期工作集怎样形成

每次准备模型上下文时，从当前任务和可见原始事件确定性重建：

1. 原样保存当前目标、验收条件、revision、输入及依赖状态。
2. 从当前可见的人工消息和回答中保存完整文本与原事件序号。否定词、时区、币种、截止日和变更要求不经过模型改写。
3. 加入当前可见的待处理请求，保留它为什么让执行停止。
4. 保存已完成依赖、子任务和前一题的交付引用：task/run、artifact IDs、bundle IDs、版本摘要及归属。摘要最多 600 字符，声明只是作者交付说明，不能代替检验。审查任务另有结构化 review_target，确保审的是指定版本而不是重做一份。
5. 保留最近有效工具结果的事件引用。大正文和代码只放预览，完整内容仍能通过对应文件/来源或事件读取接口取得。
6. 加入 Agent 通过 `memory.working_set` 登记的假设、未解决问题。每条必须有文字和可见证据 ID；假设不会因为出现在摘要中变成“已确认需求”。
7. 阅读台账保留本任务已打开文件的范围、函数/类名、页面摘要，以及来源读取区间与精确引文事件引用。只证明打开过，不证明理解；引文预览截短时必须按原事件取全文。
8. 保存摘要版本、task revision 和摘要 digest，供重启与复核使用。

### 看板重试中的增量修正（2026-11-22）

文件 write/append/replace 统一返回实际落盘字节的 SHA256 和 changed；工作集的 progress.recent_output_versions 保留最近八个有变化的产出及原事件号。检查点与工作集使用同一个事件重放函数计算未产出调用数：相同内容写入、空追加、无变化替换、恢复本任务已经出现的文件版本，以及重复发布相同摘要的集合，不清零。历史缺少摘要的结果保留旧语义，不伪造历史版本。字节变化只表示可观察变化，不能证明内容质量，新增无用文字仍需审查识别。

检验台账保留引擎记录的源码快照摘要。此后当前任务的文件工具改动相关源码时，旧检验标记 needs_recheck；该标记是提醒，不取代最终审查已有的完整版本校验。浏览器结果继续绑定不可变 bundle。code.run 等其他渠道产生的修改仍由最终源码快照校验负责，工作集不声称能观察所有写入。

最近失败仅在同工具、同参数成功后清除；无关读取、写入和其他测试成功不能清掉它。当前只展示最近一项诊断，完整失败及后续检验保留在原始事件和检验台账，不把这一字段当作所有缺陷的完整列表。上述修正不提升长期记忆的可信状态，也不改变人工验收要求。

平台维护还有一种显式纠错途径：仅由操作员维护事件携带 resolved_error_seqs 指向已修复的具体错误。工作集清除对应的当前诊断，近期错误索引标注修复事件号；原错误事件不删除。普通测试假设、网页/工具返回中的同名文本和无关错误号不具有这一作用。自测试维护回答仅对通用程序错误请求登记此前错误事件，不能据此代答业务问题或验收。

无进展控制同样消费这一内容身份：真正新产出会开启新的重复观察窗口，无变化或恢复已见版本的写入不会。临时检查点拒绝返回 executed=false 的结构化反馈，多种被拒工具交替调用共用无进展签名；不会把工作流门槛包装成需要客户修复的程序错误，真正权限与参数错误仍按原规则处理。

如果常规压缩后仍超预算，先将检验台账降为事件引用、结果状态与版本摘要，并将阅读目录降为路径、事件号与已读范围，再判定受保护需求是否真的超限。完整原始人工约束不走这一级压缩，完整工具输出仍按事件分页读取。

补充执行目录与接口记忆：code.run 可显式传 cwd，结果和检验台账保留实际执行目录，防止多份源码并存时测到旧根目录。文件分页返回规范化文本的 text_sha256（不是产物字节摘要）；阅读台账在同一文本版本累积观察到的符号和简短签名。后续页面不含函数定义时，已有签名不会被抹掉；文件工具写入或新读取版本变化会清除旧接口。摘要是观察记录，不是兼容性承诺，原文件和事件仍可复核。

精确替换失配时，检查点可提供一次冲突路径的有限阅读，必须显式 limit≤1500；仍与原始 files.read 权限取交集，不允许读取其他路径。阅读不清零产出计数，新写入前不会普遍恢复读取。失败日志保存末尾以保留常见 traceback；同路径的新版本可解除精确编辑冲突诊断，但不代表业务测试已通过。

补充失败定位与最终预算行为：code.run 可在失败结果中附上最多三个 workspace 内 traceback 对应的源码片段，每段≤1000 字符。路径文本不可信，仍经过 safe_path、文件大小和格式检查；片段仅用于定位，不改变测试失败状态或任何记忆可信等级。这项输出已有真实 Docker 控制，尚未在预算已耗尽的看板重试中验证模型收益。若可重建目录降为引用后上下文仍无法装入，则以 context_budget_exceeded 本地暂停，保留原需求与队列，不再泛化为客户澄清。

当前不再用模型反复总结整份对话，因此摘要不会引入额外模型调用。它也不能根据文笔好坏决定事实是否成立。

宿主明确标记的维护说明使用 `purpose=platform_maintenance`；旧维护事件可由宿主在独立的 operator_event_classes 映射中归类，追加元数据说明，原事件文本不改。工作集保存 maintenance_refs，不把已解决的维修日志不断累积为不可删除的客户需求。Agent 无权修改该分类。真实 human_message / human_answer 不受此维护过滤影响。

自动自测的操作员输入有单独的 `test_operator_assumption` 标记。它们是测试条件，不伪装成真实用户偏好或真实人工回答。

## 4. 上下文预算怎样控制

`CONTEXT_INPUT_BUDGET` 默认 24000 个**估算**输入 token；输出仍使用已有配置。没有提供商 tokenizer 时，使用 UTF-8 字节数除以二作保守工程估计，不能把它当作实际账单 token。

输入中只放一份原样目标与验收条件；工作集使用明确 goal_ref / criteria_ref，持久化工作集仍保存全文。长期有效指导最多使用总预算的 15%，候选最多使用 5%；超出的可见记录保留 ID，按需 inspect。

模型输入包含原始角色和系统规则、当前任务契约、工作集、可见任务/产物/来源登记、近期动作和证据，以及分级记忆。工具描述只在系统消息中传一次。

压缩首先移除较早工具结果的预览；优先的是当前任务最近一次真实工具结果，随后产生的上下文错误不会挤掉它。可重建的目录、旧产物路径、重复计划和候选预览先退为有权限的 ID 引用，再缩减最近返回页面。最新工具返回拥有优先预算，正常大小的已请求页面尽量完整保留。超长结果同时保留开头和后段，避免丢失 traceback；需要中间部分时，使用不超过 1500 字符并递增 offset 的分页。之后再缩短近期动作及证据输出尾部，必要时精简来源登记。实际事件、文件、来源正文和哈希不会被删除，当前人工约束和验收条件是受保护部分。

旧产物路径与重复计划也有预算：必要时只保留产物 ID/哈希、计划事件引用和限长预览。近期检验台账独立保存同一实际输入的最后结果，最多六项，真实浏览器与测试优先；读很多文件不会挤走成功或失败检查。记录 exit_code 不等于批准验收，修改源码后仍需检验指定版本。

格式错误的模型响应单独保留为 invalid_agent_response，工具失败保留错误和原动作；它们不再作为下一次的有效动作范例。可无歧义解释的单工具封装只做语法规范化，不修改任务条件或工具权限。

如果受保护内容本身超过预算，引擎明确报错，要求分页组织输入或显式调整预算；不会静默删掉“不要删除取消记录”之类的约束。

每次调用记录 `context_assembled`：原始/压缩后估算量、丢弃的旧预览数量、检索到的记忆 ID、工作集 digest 和任务 revision。检索命中不等于模型实际采用，更不等于证明质量提升。

## 5. 长期记忆记录包含什么

每条记录包括：

- 身份与版本：`id`、`version`、`group`、`owner`、创建/更新时间。
- 类型：`episodic`、`semantic`、`procedural`、`preference`。
- 可见性：`visibility`、`origin_scope`、`conversation_id`。
- 内容与适用范围：`content`、`scope.conditions`、`scope.capabilities`、可选数据集或交付摘要。
- 可信状态：`status`、支持和反对事件引用、校验人/理由。
- 时效及替代：`valid_until`、`supersedes`。
- 结果标签：例如 `peer_approved`、`human_accepted`、`review_rejected`、`automated_test_passed`。

结果标签回答“产生它的工作如何结束”，不能证明教训本身正确。例如，一个被人类接受的软件交付，其作者提出的经验仍可能只是 `candidate`。

相同角色、原始会话、类型、规范化内容及条件生成稳定身份。同一经验的新支持引用去重合并，内容变化产生不同身份，可通过 `supersedes` 建立修正关系。不会因重复调用而增加两份同一支持。

## 6. 状态和提升规则

`candidate` 是新候选；`legacy_unverified` 是旧日志导入内容。两者独立显示，不能作为已验证指导。

`peer_validated` 表示独立角色验证过这条经验的适用性；校验角色必须不同于作者，并提供自己可见的实际证据。普通工作被同伴审查通过，不自动验证作者的所有总结。

`active` 需要明确人工/操作员确认。Agent 的工具列表没有提升状态或修改策略的能力，不能在 `memory.propose` 中传入可信状态。

`disputed` 表示出现反证，默认检索退出；`expired` 表示有效期或数据接口版本已经不适用；`retracted` 表示明确撤回；`superseded` 表示被指定修正记录替代。历史内容和反对证据继续保留。当前过期状态可根据原始有效期/数据头版本计算，检查结果保留原存储状态及过期原因。

有反证的记录不能直接再次提升为 active。先调查反证，提出有证据的修正记录，再明确撤回/替代旧记录。仅提出修正候选不会自动让它可信。

## 7. 写入、有限反思和崩溃恢复

Agent 可以使用 `memory.propose` 提出候选，必须提供当前作用域中真实存在的事件引用。格式、权限、长度、时区和敏感文本校验在日志写入前执行。

审查拒绝、任务完成和人工拒绝会产生候选反思。动作/工具契约错误和模型连接错误使用规则生成候选，避免每个错误额外调用模型。失败观察并不证明建议的修复已经成功。

持久化顺序如下：

1. 为操作生成确定性的 `operation_id`，把完整待写记录加入 state outbox，并原子保存 state。
2. 检查长期日志中是否已有这个操作 ID。没有才追加并 flush/fsync。
3. 标记 outbox 已投递，再保存 state。
4. 从日志重建派生索引。

在第 1 步后崩溃，重启重放未投递项；在第 2 步后崩溃，重放发现同 ID 已存在，确认投递而不重复追加和计支持。重启先恢复 outbox，再为任务组装上下文。

末尾被截断的半条 JSON 会隔离并报告；中间记录损坏则停止要求修复，不把整份记忆当作空白继续运行。删除 SQLite 索引不会丢失长期记录。

## 8. 检索怎样避免误召回

检索顺序是：群组边界 → 原始会话/角色权限 → 有效状态与有效期 → 数据/交付适用版本 → 关键词相关性 → 排序和条数上限。

默认只检索有效的 `active` 和 `peer_validated`，最多六条。候选可通过 `include_candidates=true` 单独查询；上下文将它们放在 `memory_candidates`，明确提示未验证。没有词项重叠就返回空，不为了凑六条而返回随机旧经验。

英文使用规范化词项，中文使用基础字符 n-gram。排序采用可解释的匹配词数、状态和更新时间；返回 `match_terms` 和命中理由。当前没有语义 embedding，也没有未经验证的精确置信概率。

如果记忆绑定数据集 key/digest，而同名数据集已登记新版本，旧记忆不再作为当前指导。绑定交付摘要的经验也受任务输入版本限制。金融群组的 semantic 记录默认动态且一天有效，其他群组须显式 scope.dynamic=true 才使用该默认期限；显式 valid_until 优先。动态事实过期后再次研究仍需重新核实，不把昨日市场信息当成实时行情。

## 9. 私信和共享的处理

角色私有与私信来源是两层独立约束。来自私信的记忆，即使 owner 仍是同一角色，也只在原 private task/conversation 中出现，不能进入该角色的群组任务或下一次私信。

公共任务产生的角色私有记忆，其他角色也不能查询。`memory.share` 是显式审批动作；公开来源内容通过后才变为群组可见。私信派生内容还必须提交明确脱敏后的正文并取得该次审批。

私信共享产生新的公开候选，只含允许发布的文字。它不带原私信 task/run、私有证据序号和适用条件，不把 private 标签简单改成 public。原记录继续私有。共享也不会自动提升可信状态。

索引在可信控制面，未经权限过滤的记录不参与检索排序。修改查询词、请求更多结果、猜测记忆 ID，都不能扩大可见范围。

## 10. 纠错、撤回和隐私删除

纠错示例：旧经验认为静态检查足以证明按钮工作；真实浏览器失败后，使用 `memory.challenge` 引用失败事件，旧经验进入 disputed。再提出“静态语法与真实点击分别验证”的修正候选，并绑定实际成功测试。独立校验/人工确认之后才提升；旧记录可显式标为 superseded。

普通撤回保留历史，适用于经验错误。隐私删除使用单独的 `purge` 管理操作：清除该记忆各日志版本的正文、outbox 副本及旧导入行，重建索引，保留不含原正文的 tombstone。相同身份不能被普通 propose 复活。

清除记忆不等于同时删除所有原始对话、来源、外部备份和已获授权的脱敏发布。它们是不同的保留域，需要按实际范围另行处理。本文不声称实现了跨所有备份的自动隐私擦除。

## 11. 日常操作

在项目根目录执行，`YOUR_RUNTIME` 是对应群组所在目录：

```powershell
python -m collab --runtime YOUR_RUNTIME memory software list
python -m collab --runtime YOUR_RUNTIME memory software inspect --id MEMORY_ID
python -m collab --runtime YOUR_RUNTIME memory software rebuild
```

检查输出中的原始内容、版本、范围、证据和 `approval_digest`。明确决定后，使用当前摘要进行管理操作；内容变化导致摘要不匹配时拒绝执行：

```powershell
python -m collab --runtime YOUR_RUNTIME memory software promote --id MEMORY_ID --digest INSPECTED_DIGEST --reason "已复核适用条件与证据"
python -m collab --runtime YOUR_RUNTIME memory software retract --id MEMORY_ID --digest INSPECTED_DIGEST --reason "已确认该经验错误"
python -m collab --runtime YOUR_RUNTIME memory software supersede --id OLD_MEMORY_ID --digest INSPECTED_DIGEST --reason "由已核实的新记忆替代：NEW_MEMORY_ID"
python -m collab --runtime YOUR_RUNTIME memory software purge --id MEMORY_ID --digest INSPECTED_DIGEST --reason "明确的隐私删除范围"
```

继续任务仍只使用 `/resume [N]` 或 `/resume --continuous`。记忆管理不增加第二个任务执行命令。`MEMORY_ENABLED=0` 可关闭长期检索/反思；`CONTEXT_COMPACTION_ENABLED=0` 可用于无压缩对照，仍受输入预算约束，过大时明确拒绝调用。两个开关均不删除日志或改写原始证据。

## 12. 测试与当前界限

`tests/test_memory_research.py` 覆盖候选不自动提升、无关查询为空、私信/角色隔离、明确共享、过期、反证、独立校验、去重、两处崩溃点、截断日志、重建索引、隐私清除和上下文保留约束。

`scripts/check_m3_m4.py` 用真实 Docker PDF 解析器检验正常文本、无文字、损坏件和页数限制，并构造大上下文核对预算及人工约束。真实外网 PDF 检查单独标记，不与合成控制件混算。

六题自测使用独立 runtime。当前连续性目录是 `runtime/continuity_m3_m4_20261121`；软件第一题继承了用户已验收、重新检查的 b4，其余任务需要实际执行。另两轮冷启动失败记录独立保留，不混算成六题冷启动成功。`test_passed` 与 `completed` 是不同状态：前者可以在测试群组解锁下一题，但不会计入人工验收完成率。候选反思、测试假设和自动 verdict 都保留来源标签。

当前没有实现向量检索、OCR、自动发现全部语义冲突、自动提升 prompt/skill 或通用跨场景偏好共享；它们不属于本次 M3/M4 的已完成承诺。检索轨迹和上下文缩减是可观察工程指标，不能直接证明六题质量或长期记忆收益，结果以实际测试记录为准。

## 13. 连续预约任务中的具体读写过程

以当前软件群组为例，第一题已验收的是 b4，而不是先前失效的 b1/b2。进入第二题时：

1. 根任务的工作集列出前一题交付和验收状态，并保留 b4 的 ID/哈希；子任务从委派 inputs 获得版本引用，不会自动获得其他角色 workspace。
2. 开发者显式 import_bundle，拿到不可变源码副本；操作员显式交接只读预约快照，快照 SHA 与归档授权核对一致才可登记。真实预约数据与测试 fixture 分开。
3. 短期工作集保留“取消记录不能删除”、日期范围、时区和最新验收条件；数据登记版本记录 snapshot digest。它们是执行约束与事实输入，不是长期经验的自然语言替代品。
4. 开发完成、QA 拒绝或浏览器失败可以形成 procedural/episodic 候选。例如“静态语法检查不代表按钮可用”必须引用实际失败事件，仍不能自动成为 active。
5. 下一次检索只有范围/权限/时间/数据版本均合适时才参与相关性评分。没有可信长期指导也可以继续任务：原始需求、短期工作集、版本化交付和证据仍然可用。
6. 新快照替换了同名数据头后，旧统计经验失效；更正公式时保留反证，提出修正候选；独立复核或明确人工确认只作用于指定记忆。
7. 同一个群组继续第二题不代表复制全部历史进 prompt。原始内容继续落盘，模型只接收当前契约、必要交付引用、预算内证据页面与符合范围的记忆。

各类型的建议内容：episodic 记录具体失败条件和结果；procedural 记录有适用前提的操作方法；semantic 记录有来源、版本和期限的接口或事实；preference 仅记录已经明确确认、授权保存的偏好。投资测试画像带 test_operator_assumption，不能被写成真实用户的长期偏好。原文引用、完整代码、逐行预约和个人信息留在各自有权限的数据域，避免复制为永久自然语言记忆。

记忆是可检查的外部记录，不是模型参数更新。本阶段只实现受控候选反思；不允许 Agent 自己改系统 prompt、提升权限或让候选经验自动改写 skill。后续演进需有独立实验、版本和回滚，再获得相应发布授权。

## 14. 失败后的进度观察

工作集新增 progress：最近三条不同的工具观察及原事件引用、工具计数、距最近写出成果的调用次数、尚未解决的最新错误。连续读取八次仍未写出文件/论断/产物时给出转向小步实现或草稿的建议。该建议不改变权限、预算或验收标准；成功工具调用也不自动代表交付成功。上下文不足时预览退为引用，原记录不删除。

研究上下文默认按当前 run 展示来源/论断；旧来源仍可按 ID 读取，历史论断通过 include_history=true 明确查询。公共历史可访问不代表已在本任务核实；私信权限继续先行过滤。实际恢复结果与仍存在的循环见 [成功与失败改进记录](success-and-failure-record.md)。

## 15. 输出检查点与来源失败记忆

工作任务在计划后连续 12 次工具调用未写出文件、论断或产物时，host 从原始事件派生 output_checkpoint，并同时收窄模型所见工具与网关允许集合；成功写入后的下一轮上下文恢复原权限。review 豁免，失败写入和工作集注释不能清零。检查点不修改最终验收或增加权限。

source_failures 是可检查的运行状态，不是可信长期事实：公共 URL 失败按 run 去重，私信按 task 隔离。已知不可访问与瞬时错误分别有限尝试，返回未核实结果；不会因此将缺失来源提升为已验证。详见 [流程修复](workflow-failure-remediation.md)。
