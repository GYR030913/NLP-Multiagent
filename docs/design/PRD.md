- 关联：[技术与架构](ARCHITECTURE.md)、[实现路线](ROADMAP.md)。

## 1. 产品定位与目标

Campus Collab 是课程用多智能体协作平台。人类向一个四角色群组提出目标，团队自主澄清、规划、委派、执行、审查和返工，最终交付可检查的产物。平台负责可靠执行和边界控制，模型负责方案选择和内容生成。

首个目标是用相同平台完成三个场景的六项连续任务，并能解释“谁做了什么、依据什么、哪里失败、用了多少资源”。同场景 Task 2 继承 Task 1 的对话、公开产物和允许读取的记忆，不重新假装冷启动。

第二个目标是在固定实验条件下验证记忆和演进的收益。记忆数量增加、prompt 变长、模型自评更高都不构成质量提升的证据。

## 2. 使用者和基本约束

- 人类请求者：发布任务、补充真实需求、检查交付、批准敏感操作和最终验收。
- 团队开发者：维护工具、技能、记忆和调度；不修改原始任务来制造成功。
- 评估者：复核完整记录、产物、来源与指标，区分开发试跑和正式实验。

保留 `NLP_Mid_Test/` 中的四角色身份和任务原文。场景技能提供可选工作方法，不代替角色原文，不预填人类问答，不预先写好六题答案。平台使用课程允许的 HKGAI/DeepSeek 接口，不加入其他提供商的自动回退。

## 3. 当前能力与待补缺口

### 3.1 可复用的现有能力

`cli.py`、`engine.py` 已实现群聊/私信、任务计划、多级委派、依赖、审批、审查和返工；`tools.py`、`sandbox.py` 已提供文件、Docker、搜索、文本抓取、产物和 Git 工具；`store.py` 已有状态保存及按角色的 JSONL 经验；`report.py` 和评测脚本已有指标及六题聚合。

当前还有独立审查证据校验、累计动作预算、断连恢复、curl/urllib 传输选择及 JavaScript 静态检查。这些应通过增量扩展复用，不从零重写。

### 3.2 主要缺口

- 任务进度缺少面向用户的摘要，动作上限暂停容易被理解为故障。
- 单文件发布/导入重复调用多，交付集合及版本关系不够明确。
- 软件检查偏向静态语法和 API，缺少统一的浏览器交互证据。
- 搜索片段、已打开正文与具体论断缺少统一证据映射；研究 PDF 和数据处理能力不足。
- 长期记忆目前主要是模型生成的经验文本及关键词检索，缺少失效、反证、纠错和范围控制。
- 尚无版本化 skill 注册、能力匹配及受控 prompt 演进流程。

代码具备某种能力与某道真实任务已验收是两回事。其他成员电脑上的验收记录不能替代本次运行的 `runtime/` 证据。

## 4. 范围与优先级

**P0，形成工程闭环必需**：保留既有能力；明确执行状态；任务契约；skill 注册；批量产物；独立验证；可溯源记忆；断点恢复；六题指标。

**P1，支撑六题真实质量**：浏览器验证、受限 PDF 文本提取、结构化来源及论断台账、只读数据分析、短期压缩、长期纠错与检索改进。

**P2，建立基线后实施**：prompt/skill 候选演进、跨任务策略实验、人工确认后的版本提升；可选有限并行。

本轮不包含通用 Web 聊天产品、企业多租户、真实证券交易、新闻自动发布、任意联网 shell、自动增权、模型权重训练。金融和新闻任务仍要求真实研究及人类判断，不能用免责声明替代内容质量。

## 5. 三个场景与六项任务

下面是推荐逻辑及验收要求；允许团队根据人类澄清调整任务拆分和角色协商顺序。角色分工由能力与任务契约决定，不把每个角色固定在唯一流水线位置。

### S1 软件团队

角色：`lead`、`dev`、`qa`、`release`。

**S1-T1 会议室预约系统**

推荐逻辑：负责人明确时区、房间及取消权限 → 提出验收条件和任务 DAG → 开发实现持久化、冲突控制及 UI → QA 从干净交付集合独立测试 → 发布角色整理运行说明和版本 → 独立根审查 → 人类浏览器验收。

必须交付可运行源码、测试、使用说明、产物清单。验收覆盖查询、预约、取消、重启持久化、同房间重叠拒绝、相邻预约允许、非法输入及并发双订；浏览器真实按钮操作和 API 测试分别留证据。推荐采用半开区间 `[start,end)`，具体时区和跨日约定必须显式记录。

**S1-T2 房间使用率看板**

先识别 T1 的已接受交付及数据契约；若 T1 取消操作未保留记录，先提出兼容迁移，不能凭空计算取消率。看板按日期范围读取真实预约记录，展示预约次数、时长、繁忙日/时段和取消率，给出房间分配建议。

必须声明时间范围、跨日裁剪、取消记录口径和取消率分母。建议定义：预约次数按与查询窗口重叠的记录计；活跃预订时长按交集计；取消率按同一口径下取消记录数/全部记录数计。方案可以调整，但需经需求确认并使用已知数据独立复算。分析和测试使用数据库快照，不破坏 T1 数据；浏览器日期选择和无数据状态可用。

### S2 新闻编辑部

角色：`chief_editor`、`reporter`、`fact_checker`、`editor`。

**S2-T1 校园 AI 新闻**

主编协商读者、时效和选题；记者查找学校公告等一手来源并打开正文；事实核查角色检查时间、核心论断、矛盾及遗漏；编辑生成适合不同渠道的版本；独立审查后交人类验收。

交付新闻正文、校园短讯/社交摘要、来源及论断台账、事实核查说明。关键事实必须可定位到正文或受控 PDF 的具体片段；搜索片段只用于发现线索。不得虚构采访、引语或未观察到的事件。

**S2-T2 AI 写作检测事实核查**

先界定“可靠”与“判断某一份作业”，检索一手论文、评测、工具限制和高校政策，分析误报/漏报、基准发生率、语言和学科差异。事实核查者主动找反例，编辑分别向学生与教师解释结论和不确定性。

交付面向读者的文章、claim-to-source 台账、相反证据和局限。不得把工具自述或单一检测分数当成学术不端证明。无法访问原文必须标记，不把摘要当作全文核实。

### S3 证券基金团队

角色：`fund_manager`、`research`、`risk`、`marketing`。

**S3-T1 模拟投资建议**

基金经理和客户沟通角色先询问投资期限、流动性和风险偏好；研究角色搜集有日期的市场/证券资料；风险角色独立复算配置并分析集中度、汇率及下行情景；沟通角色输出易懂说明；最终由人类验收。

以 HKD 1,000,000 为输入，权重与金额必须吻合；汇率、费用和现金处理有假设及日期。没有历史数据时不生成貌似精确的波动率和相关系数。只输出模拟方案，不连接券商下单。

**S3-T2 半导体行业 HTML 幻灯片**

团队自主确定研究范围，区分事实、估计和预测；研究覆盖支撑判断的产业链、供需、资本开支、竞争和政策，风险角色提出反证，沟通角色制作逐页 HTML，独立检查逻辑、来源及浏览器交互。

要求年末视角时仍以实际可获取数据为准。在 2026 年年底之前运行，必须标明数据截止日，把之后的判断标为情景预测。交付可本机打开、有键盘导航的 HTML、使用说明、来源和风险说明，不依赖必须联网的 CDN。

## 6. 产品需求

### FR-01 任务契约与子 Agent 派发（P0）

每个子任务包含目标、负责人、验收条件、依赖、输入产物、允许工具、skill 版本、预算及输出要求。负责人必须是当前场景四角色之一。子任务上下文独立装配，不复制整个聊天历史；公开证据引用与私信边界不能因委派而扩大。

调度器只派发就绪节点；工作结果经独立审查后才解锁依赖。不得自审、依赖循环或重复创建同一交付任务。重新派发保留原任务 ID、尝试编号及失败历史，不把重试当作新成功样本。

### FR-02 可持续运行与可观察性（P0）

执行与继续只提供 `/resume` 一个命令入口，模式通过参数选择，不新增同功能命令。保留 `/resume` 默认最多执行 30 个动作及 `/resume N` 分批执行；新增 `/resume --continuous`，自动跨内部批次推进，直到满足停止条件。显式动作数 N 与 `--continuous` 互斥，参数冲突时提示用法，不静默忽略。

两种模式均遵守已配置的根/子任务总预算，恢复和切换模式不重置已消耗预算。遇到待处理或新产生的人工请求、预算耗尽、不可恢复错误或完成时停止；重复无进展、可重试错误经有限重试仍失败时，也暂停并解释原因。用户可中断，重启后恢复已保存状态；连续执行授权只对本次调用有效，不在下次启动时自动续跑，也不自动回答或批准请求。

新增进度摘要：当前目标、执行模式、运行/等待/审查节点、最近有效产物、停止原因、已用/剩余预算、实际费用可知部分及下一步命令。分批模式达到 N 次只显示“本批次结束”；连续模式内部换批不要求再次输入命令。任务的持久化 `running` 与进程正在调用模型必须分开展示。

### FR-03 可版本化 skills（P0/P1）

skill 是提供给模型的可复用工作方法，包含适用条件、输入、建议步骤、工具需求、输出契约和验收检查。不是测试题答案，也不是自动执行任意脚本的通行证。

首批包括：需求澄清、计划委派、软件构建、独立软件验证、发布交付、可追溯研究、事实核查、证据写作、模拟组合分析、行业分析和 HTML 演示。每次使用记录版本；skill 声明的权限只能是角色/任务已有权限的子集。

### FR-04 工具网关与交付集合（P0/P1）

保留文件、代码、搜索、抓取、Git 等现有工具。新增机器可读注册表，向模型说明参数、格式、资源上限、网络和审批要求。新工具优先补充：批量发布/导入及校验、浏览器验证、PDF 提取、论断台账、受限数据分析、记忆查询和演进候选检查。

同一交付集合包含全部必要文件及哈希；QA 一次导入完整集合，避免漏文件和重复动作。默认交付源码目录及 manifest，不把 ZIP 当成必须可发布的格式。

### FR-05 短期记忆（P1）

记录当前目标、已确认需求、有效计划、当前依赖、最近工具结果摘要、未解决问题和待验证假设。它是有来源的工作集，不存未经核实的“永久事实”。短期指用途和有效期，不等于只能放内存；重启后应可恢复。

上下文按预算装配，保留证据 ID 和产物引用，避免每一步携带整份源码或全部网页。压缩不得删除人类约束或将假设改成已确认事实。

### FR-06 长期记忆（P1）

记录跨任务可复用且有证据的操作经验、失败原因、稳定的数据接口和已确认偏好。区分情节记忆、语义事实、程序性经验；记录范围、有效期、出处和支持/反对证据。

未审查的模型反思只能进入候选区。peer-approved、human-accepted 是结果标签，不等于客观真理；后续人类拒绝或反证必须撤销/替代相关经验。读写和索引均先执行群组、角色、私信权限过滤。跨角色共享由发布者显式提出，敏感内容需确认。

### FR-07 受控自进化（P2）

**可以加入 prompt 自进化**，但只允许修改受版本管理的附加指导层。原始角色提示词、工具权限、审批、预算、验收标准及评测代码不可被候选修改。

允许的其他演进：失败反思、记忆纠错、skill 建议步骤优化、检索排序/工作集压缩策略优化。Agent 可提出新增工具或代码补丁需求，但只能进入普通工程评审流程，不可自动部署。

演进必须经过提案、验证、对照评测、人类确认、下轮启用和回滚。每次正式实验固定 prompt/skill/策略版本，运行中不热更新；有改善证据之前只称“候选优化”，不称“已进化”。

### FR-08 证据与指标（P0/P1）

每次审查逐项对应验收条件，并引用当前审查者实际取得的工具证据。产物、数据版本或核心前提变化后，旧证据变为失效，需重验。

同时报告：六题固定分母完成率、已尝试成功率、工作子任务完成率、耗时、人工等待、动作数、模型调用、返回 token、重试及未返回用量。新增记忆命中/失效、重复导入、返工、证据覆盖和候选版本指标。传输重试次数与调度动作数分开记录，不能推算未知真实费用。

## 7. 非功能要求与通过条件

- 可恢复：在状态保存、产物写入、记忆提升和工具返回之间注入中断，恢复后不丢失已确认事实，不重复危险外部操作。
- 隔离：默认不共享工作目录，不把模型密钥挂进容器；浏览器验证不开放任意外网；受信任约束不能被网页/产物中的文字覆盖。
- 可追溯：每项交付可追到版本、执行者、来源和验证结果；正式评测记录代码、模型、镜像、prompt、skill、初始记忆及数据截止日。
- 效率：上下文有上限，批量产物减少无效重复动作；不以减少动作数为由跳过独立验证。
- 兼容：旧记录先备份迁移，原 ID 不变；旧六题匹配口径继续可解释，失败记录不能被成功重试覆盖。

第一轮完成条件：六项任务均有完整交付、独立审查和本次人类最终验收，外加跨任务复用证据。若仅完成其中若干题，应如实报告分子/6，不宣称平台已完成全部场景。

进化收益另行验收：在开发用场景变体上进行配对实验，质量与安全不退化，预算内成本可接受；真实隐藏题不得用于调 prompt 或选择候选。
