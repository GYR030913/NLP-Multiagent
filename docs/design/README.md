## 设计结论

系统仍然是让四个角色自主协作的通用 Python CLI Harness。六项课程任务用于验收，不把任务答案或唯一工作顺序硬编码成六条流水线。

建议先完善可观察执行、批量交付、证据验证和记忆纠错，跑通六题；再验证反思、技能复用及 prompt 演进是否真正改善效果。第一版保持单群组顺序调度，不引入新的常驻 Agent、向量数据库或微服务。

## 请确认的设计决策

以下设计已由用户确认；其中 M0–M2 已授权实施，其余阶段不因设计确认而自动开展。

- **D1 范围**：优先交付可完成三场景六题的 CLI 平台；统一聊天 Web UI、多人账号和云部署延后。
- **D2 技术栈**：保留 Python 3.11+ 和现有引擎；核心尽量使用标准库。浏览器自动验证采用独立 Playwright 沙箱镜像，PDF 解析采用独立可选依赖；新增依赖在相应阶段锁定版本与镜像摘要。
- **D3 Agent 派发**：保留每场景四个原始角色；“子 Agent”默认表示分配给现有角色的独立子任务上下文，不创建额外角色或真正并行进程。真实并行作为后续可选阶段。
- **D4 记忆**：短期工作集按任务隔离；长期记忆按群组、角色隔离，经过证据校验再提升。跨角色复用必须显式共享并保留出处。
- **D5 运行体验**：执行与继续统一使用 `/resume`，不另设同功能命令。保留 `/resume` 默认最多执行 30 个动作及 `/resume N` 分批执行，增加 `/resume --continuous` 连续执行模式；两种模式都受已配置的根/子任务总预算约束，恢复不会重置预算。遇到人工请求、预算耗尽、不可恢复错误或完成时停止，也支持用户中断；展示明确的停止原因、剩余预算和下一步操作。连续模式是同一命令的选项，不是无限执行或自动审批。
- **D6 自进化**：先支持有出处的反思、错误经验修正与检索策略优化；prompt/skill 修改只生成候选，经过独立验证和人类确认后才能成为下一轮默认版本。原始角色提示词、权限和评测规则不可由演进器修改。
- **D7 数据及兼容**：保留文件型运行存储和原有 ID；先备份再显式迁移旧状态。记忆检索索引可重建，不先强制迁移整个工程到数据库。
- **D8 发布边界**：本机演示与模拟研究为目标；不自动发布新闻、不真实交易、不在未获批准时推送 GitHub。
