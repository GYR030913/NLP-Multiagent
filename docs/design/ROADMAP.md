# Campus Collab 分阶段实现路线

- 版本：0.2，设计已确认；M0–M2 实施状态另见 [实施记录](../m0-m2-implementation.md)。
- 依赖：[PRD](PRD.md)、[技术与架构设计](ARCHITECTURE.md)。
- 执行前提：用户已确认 D1–D8，并先后授权 M0–M2、M3–M4 与六题自主测试；实际实现见 [M3–M4 实施记录](../m3-m4-implementation.md)。以下保留阶段目标与验收条件，不把计划或自动测试通过当作正式人工验收。

## 1. 实施原则与依赖

按“基线 → 可观察执行与契约 → 交付/软件验证 → 记忆 → 研究与数据 → 六题正式验证 → 受控演进”的顺序推进。真实并行最后独立决策，不作为六题交付的先决条件。

每个阶段完成后给用户看可运行结果、相关证据、剩余缺陷和资源使用，再进入下一阶段。用户已经批准整体设计的常规可逆开发不反复请求权限；最终验收、敏感外部操作及演进版本提升仍由人类明确确认。

优先使用小 PR/提交；实际实现分支为 `codex/m0-m2-harness`，保持原成员 A 分支可回退。阶段可以独立验证，但不能把未通过的前置能力掩盖在后续演示里。

不承诺尚未讨论的完成日期。M0 确定截止时间、人数、模型额度和依赖下载条件后，再估算排期；这里的阶段顺序与出口不依赖人数假设。

## 2. M0：基线封存与设计确认

**目的**：弄清楚“原来能做什么、这次改好了什么”，先保护本机数据。

工作项：

1. 确认 D1–D8、课程约束、最终材料格式、预算和团队分工。区分平台研发任务与六项场景验收任务。
2. 记录提交 `42db55a`、Python/Node/Docker 版本、镜像摘要及配置键名；不记录密钥。
3. 在停止同群组写入后，备份 state、记忆及产物；记录哈希。保留本地 `.env.example` 和 Dockerfile 修改，基线不得含真实 token。
4. 复跑已有 105 项离线测试，以及最小模型、Docker 隔离、搜索检查，记录实际通过/跳过/失败。既有数量只是基线，之后随新增测试变化。
5. 选择少量开发变体，记录当前每任务动作、返回 token、重复读写/导入、失败恢复和交付缺项，作为成本比较基线。
6. 明确开发集与正式六题/隐藏题边界，冻结实验目录命名、初始记忆和模型设置。

交付：基线 manifest、数据备份、开发评测样本说明、范围确认记录。

出口：配置可用、原有回归无新增失败；所有关键记录可恢复；本机未完成任务仍标为未完成。确认不足或接口不可用时，允许继续独立离线工程，但不能记录真实质量通过。

回滚：未迁移任何旧数据；删除新开发工作区即可返回原基线，原运行目录不被试验覆盖。

## 3. M1：运行控制、任务契约和 Skill/Tool 注册

**对应需求**：FR-01、FR-02、FR-03、FR-04、FR-08。

建议涉及：`cli.py`、`engine.py`、`contracts.py`，新增 `runner.py`、`context.py`、`skills.py`、`tool_registry.py` 及首批 skill manifest/正文。

工作项：

1. 定义 schema v2、任务 inputs/outputs/allowed_tools/budget/revision 等字段，保持已有 ID 和状态语义。
2. 增加机器可读工具注册及参数/权限前置校验；旧 Tools 返回值通过适配器兼容，不一次重写工具本体。
3. 先实现澄清、规划委派、软件构建、独立验证、发布五个 skills，固定版本和内容哈希。
4. 角色能力建议、重复交付键、预算预留和依赖错误反馈进入调度器；私有任务仍禁止公共委派和产物传播，并使用独立 private workspace，公共任务无法通过工具读取私有文件。
5. 统一执行入口为 `/resume`，保留无参数默认 30 步和 `/resume N` 分批模式，新增 `/resume --continuous` 参数，不增加同功能命令。补充 status 的执行模式、停止原因、已用/剩余预算、活跃进程、等待节点及下一步操作。一个任务存在不等于进程正运行。
6. 模型网络尝试次数与调度动作分别计数，显示未知用量；无进展检测使用有效输出变化而不只比较工具名。
7. 实现迁移 dry-run 与显式迁移；先在旧运行目录副本验证，不在用户正在使用的原目录试错。

验收：

- 假模型可从 plan → delegate → 依赖 → 独立 review → 人类 acceptance 完成一条链路。
- 非法委派原子拒绝，无残留任务；重复交付键不重复创建节点；自审、循环、越权仍被拦截。
- `/resume` 默认最多执行 30 次动作，`/resume 3` 最多执行 3 次；`/resume --continuous` 自动跨内部批次推进，不要求每批再输入命令。N 与 `--continuous` 同时出现时，调用模型前拒绝并提示用法。
- 两种模式在既有/新增人工请求、预算耗尽、不可恢复错误、完成或用户中断时交回控制权，显示明确原因和剩余预算；重试耗尽、无进展也明确暂停。存在待处理请求时不继续调用模型，不自动审批。
- 分批与连续切换、进程重启均不重置累计预算；预算用尽后重复 `/resume` 不能继续超支。连续模式不持久化自动执行授权，重启后等待下一次显式调用。
- 在计划校验失败后重启，不能误恢复成已计划；缺 planned 字段的旧记录不被伪造为已计划。
- 未知 schema 明确拒绝写入；迁移副本的原任务、队列、审批和预算不丢失。

停止/回滚：新 runner 和 skill 选择有独立开关；v2 副本不让旧代码写入。出现状态回归，停进程并恢复 M0 副本，不用改历史状态掩盖问题。

## 4. M2：批量产物与软件场景验证闭环

**对应需求**：FR-04、FR-08，S1-T1、S1-T2。

建议涉及：`tools.py`、`sandbox.py`、`ui_check.py`、交付/预览脚本及新 bundle/browser 适配器。浏览器镜像独立于原 Python 沙箱。

工作项：

1. 实现 publish_bundle/import_bundle/validate_bundle，维护 manifest、入口、输入数据契约及逐文件摘要。
2. 先写临时 blob/目录，全部验证后暴露集合；兼容原单文件发布，不强制 ZIP，也不扩大任意二进制权限。
3. 加入受限 `browser.verify` 和可回收 preview lease，确保应用与浏览器同容器、本机预览仅 127.0.0.1。
4. 软件验证 skill 分别检查逻辑测试、API、JavaScript 和浏览器点击；根审查逐项消费本次版本证据。
5. 在新的开发运行副本完成预约系统，人工实际验证预约、冲突、取消及重启；数据模型保留取消历史。
6. 在相同开发群组继续看板，复用真实数据库契约与数据快照。若前题 schema 不足，先交付并验证兼容迁移，不另造假数据声称复用。

验收：

- 包含 10 个文件的集合可一次发布、一次导入；每个文件仍可核对哈希。缺文件、坏哈希、路径越界和静态 JS 错误时整个提交拒绝。
- 人为植入的“HTTP/API 正常但按钮 JS 失效”必须被浏览器验证或人工验收拒绝。
- 两个并发请求不能双订同一时段；相邻预约有效；取消后可重订；重启保存；无数据界面正常。
- 看板对已知记录的次数、裁剪时长、繁忙时段、取消率能独立复算；含跨日、边界、取消与空数据用例。
- 网络、文件系统和秘密边界与原沙箱一致；浏览器测试不能访问宿主秘密、任意外网或其他 Agent 目录。
- 原单文件交付记录仍可导出；新的预览不修改不可变交付源码。

本阶段的两题作为开发验证，不与后续固定版本的正式六题混合报告。

回滚：关闭新 bundle/browser 工具并保留旧路径；生成物与数据库均留在隔离开发 runtime，原预约记录不被迁移演示破坏。

## 5. M3：短期工作集与长期记忆管理

**对应需求**：FR-05、FR-06、FR-08。

建议涉及：`store.py`、`context.py`、新增 `memory.py`、memory outbox 与检索适配器。先确定性关键词/FTS，不先引入向量服务。

工作项：

1. 实现 per-task 工作集、关键约束和待验证假设的有来源摘要，以及上下文分块预算。
2. 实现记忆类型、作用域、版本、证据、有效期和状态；旧 JSONL 导入为 legacy_unverified，不直接提升。
3. 实现 propose/search/inspect/challenge/share，角色隔离先于检索排序。
4. 用 state outbox 与 operation_id 连接审查/验收事件和长期日志，保证崩溃重放不重复计支持。
5. 加入去重、反证、disputed/expired/retracted/superseded、索引重建及敏感内容清除流程。
6. 有限触发反思：优先规则归类，复杂失败才产生模型候选；成功经验同样需要明确适用条件。
7. 在同一代码版本上做短期、长期、纠错的逐项开发对照，记录每次检索为何命中、是否过期及实际应用结果。

验收：

- “旧 JS 曾被误判通过”的经验遇到真实反证后退出有效指导，修正版本可追溯；错误记忆不能永久污染下一题。
- QA 不读到开发私信，跨场景不读到个人投资偏好；同角色的公共任务也不能召回其私信派生记忆。修改查询文本不能越权召回。
- 动态金融事实过期后不作为当前事实，稳定数据接口变更后旧 schema 经验失效。
- 压缩前后保留时区、否定要求、验收版本、未解决问题和证据 ID；重启能恢复工作集。
- 在 outbox 写入/日志追加/确认之间模拟崩溃，恢复不产生两条有效同 ID 记忆或重复支持计数。
- 删除索引后能重建，FTS5 不可用时能回退；无相关内容时返回空，不返回六条随机经验。
- 长期记忆候选和 active 状态在 UI/导出可区分，反思文本不能直接获得可信状态。

回滚：关闭长期检索和压缩即可运行原任务链；新格式日志独立存放，原记忆日志保持可恢复。不能将 v2 内部状态回写旧 JSONL 冒充旧版兼容。

## 6. M4：可溯源研究、事实核查与受限数据分析

**对应需求**：FR-03、FR-04、FR-08，S2 与 S3 四题。

建议涉及：搜索/抓取适配器、source/claim/dataset schema、PDF 解析镜像、`data.analyze`、研究/事实核查/金融/HTML skills。

工作项：

1. 补充有来源正文、日期及偏移/PDF 页码的 source ledger 和 claim ledger，显式区分发现线索与已读原文。
2. 实现受限 fetch_document/extract，包括断网解析、超限拒绝和扫描件质量报告；没有文字不能假装全文已核实。
3. 实现 data.register 和有限分析 spec，保留数据快照、币种、时区、汇率及计算公式；复杂自定义计算仍走 Docker。
4. 落地研究、核查、写作、模拟组合、行业分析和 HTML 演示 skills。
5. 新闻两题用真实来源进行开发试跑，重点找相反证据和不确定性；金融两题区分客户假设、数据事实及未来预测。
6. HTML 以本机可打开和逐页操作为验收，来源与数据日期不能仅藏在外部链接中。

验收：

- 打不开正文的来源被降级，搜索片段不能满足关键论断的“原文已核实”。同一事件的发表/发生/检索时间分别保留。
- 私有地址、重定向到内网、伪装 PDF、过大 PDF、解析超时被拦截；没有宿主解析生成代码的降级路径。
- 支持和反对证据可同时存在；台账不能因审核者不喜欢结论而删除反证。
- 构造基准发生率和误报示例，核查材料不得将检测分数表述为作业来源的确定性结论。
- 投资权重、金额、现金、费用及换算独立复算；缺少数据时不能返回精确相关系数；无真实交易调用。
- 半导体 HTML 可离线逐页和键盘操作，显示数据截止日，未来判断标注为情景；可由浏览器验证工具重演。

回滚：禁用单独的 PDF/数据扩展不影响纯文本工具。需要原文/PDF 的检查保持 blocked，不能因降级把任务标为通过。

## 7. M5：固定版本的六题正式验证与交付

**对应需求**：FR-01 至 FR-06、FR-08 和六题全部场景要求。

工作项：

1. 冻结代码、模型、skill、prompt、检索策略、镜像摘要和初始记忆。采用独立正式 runtime，保留开发记录但不合并计分。
2. 三场景分别创建四角色群组。每场景先 T1 后 T2；第二题在相同群组继续。人类按真实请求回答，不预设问答脚本。
3. 每题收集 plan/DAG、执行、来源、数据、交付集合、独立审查、人工最终验收和记忆快照。
4. 遇到故障优先恢复原 run，完整记录失败及重试；不能丢弃首个失败目标只保留后来成功。
5. 生成固定六题与按尝试的两种完成率，包含人工等待、未知费用和失败原因；与本机浏览器/来源复核相互核对。
6. 打包可复现示例，检查不含 `.env`、token、私信及真实个人数据。是否推送 GitHub 按批准的仓库/分支单独执行。

出口：

- 目标是六题全部获得本次独立审查及人类验收；未达成如实列为未完成，不进入“全场景已完成”的宣传。
- T2 对 T1 的继承可用输入 bundle/dataset/记忆 ID 证明，不能只有模型口头声称。
- 所有结果可从导出重算，源证据与产物哈希一致，未尝试题不会从分母消失。
- 人类可从干净导出启动软件、打开幻灯片并核验研究依据。

这是主要工程交付点。若课程时间不足，优先保证本阶段的真实交付和诚实报告，P2 演进不抢占六题验收资源。

## 8. M6：受控反思、Skill 与 Prompt 演进

**前置条件**：M5 的基线可复现；安全和评测不变量稳定。对应 FR-07。

工作项：

1. 实现候选 schema、白名单补丁、版本固定、evolution 状态和独立实验预算。
2. 先做程序性经验提取/skill 建议步骤优化，再做 prompt overlay；原始角色及核心规则保持只读。
3. 配对 baseline/candidate，固定数据与初始记忆，在开发变体上重复实验；不使用正式题结果调参，不接触隐藏题。
4. 输出候选变更、支持/反对证据、各场景结果、费用和局限。评估者不看候选标签，自动 judge 不能替代最终人类验收。
5. 人类确认后下一新运行使用新版本，保留上一默认版本和回滚接口。

验收：

- 要求“取消审批”“提高工具权限”“改评分分母”的候选必须被拒绝，即使自评声称质量更高。
- 候选不能读取私有运行数据作为通用训练资料，不能把网页指令提升为策略。
- 参考初始门槛：每场景两个开发变体、各三次重复；安全零退化，各场景成功数/人工质量不下降，同质量时 median 动作/token 不高于基线 110%。特殊更贵候选只能人工权衡。
- 显示原始样本及未知费用；提供商不支持 seed 时明确说明，少样本不作显著性承诺。
- 正式运行开始后修改默认 overlay，不影响该运行已固定版本；回滚后新任务读取旧默认，旧记录保持原版本。
- 没有候选满足门槛时保持基线；“没有改进”是合法实验结果，不强制产生新 prompt。

回滚：关闭演进器、回到旧默认版本；不删除历史失败、旧记忆或候选实验记录。不可自动修改代码并上线。

## 9. M7：可选有限并行与后续扩展

仅在六题闭环和成本评测稳定、确有瓶颈时决定是否实施。

先加入任务租约、每任务 workspace、单写入协调器和预算原子预留，再开放最多 2 个独立就绪节点并发。验证断连/超时/重启后不会重复派发或超预算，同角色不能竞争覆盖文件，审批不能串用。

并行是否更快须结合 API 限流、上下文成本和完整任务耗时验证；不能把四个角色身份数量当成四路并发性能。统一 Web UI、向量索引、OCR、更多数据源等分别立项，不能挤进已有承诺。

## 10. 质量验证与实施粒度

每个阶段只运行与变更相关的必要检查，阶段出口再做完整回归。文档/低风险可逆调整不编造镜像实现的测试；任务状态、权限、记忆和演进需要实际反例测试。

测试层次：

- 状态机/契约：假模型驱动、预算边界、依赖无环、身份隔离、非法动作原子拒绝。
- 组件：真实文件/manifest、记忆反证与日志重建、数据公式、候选版本和迁移。
- 故障注入：状态落盘、工具副作用、记忆 outbox、超时和重启之间的中断。
- 集成：真实 Docker、浏览器、PDF、受控联网；不能用 mocked Docker 报告真实执行通过。
- 端到端：六题真实协作与人类验收；自动内容评分只作辅助。

建议 PR 粒度按“状态及兼容 → 注册/runner → 产物集合 → 浏览器 → 工作集 → 长期记忆 → 来源/PDF → 数据/研究 skills → 六题验证 → 演进”划分；遇到接口耦合允许合并相邻 PR，但每个必须有可独立复核的行为变化。

## 11. 配置和资源策略

保留已有 `.env` 键及本地 `.env.example` 修改；新配置通过补充说明/专用策略文件引入，不重写本地模板。候选配置如下，名称可在实现 PR 中确定：

- 运行：`/resume` 本次调用的分批/连续选项、默认批次大小、无进展阈值、根/任务预算、模型请求上限；不配置第二个执行命令或重启后自动续跑。
- 上下文：输入预算、片段上限、长期记忆条数和压缩开关。
- 记忆：日志版本、候选状态过滤、有效期、共享策略和索引适配器。
- 扩展：浏览器/PDF 镜像摘要、大小/页数/超时、预览 lease 与端口。
- 演进：默认关闭、候选上限、专用实验预算、开发集 ID 和人工提升开关。

数据库与来源资料有明确最大尺寸、磁盘水位及清理规则；清理不删除人类尚未验收的交付或正式实验原始证据。模型重试和演进均消耗真实额度，M0 需确认费用上限；没有价格表时以动作/token 限制，费用显示未知。
