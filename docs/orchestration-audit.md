## 主要结论

1. 现有 `Engine` 已具备可运行的编排骨架，尤其是真实子任务创建、依赖唤醒、独立审查、返工记忆、人类审批和重启入队。后续不应重写框架。
2. 最大缺口不是“完全没有功能”，而是缺少稳定契约和边界测试。最先需要结构化的是 Agent 能力、消息信封、工具/记忆/人类接口和运行级预算。
3. `engine.py` 同时承担模型循环、消息可见性、任务图、状态转换、审查和人类请求。直接拆分会增加冲突风险，因此应先通过不改变外部行为的辅助模块和适配器迁移，再逐步把逻辑从 Engine 中移出。
4. 当前 69 项测试足以证明已有状态机没有明显回归，但不足以证明多级委派、所有失败传播和 Task 2 的真实复用。

## 非目标与限制

- 本次审计没有修改运行状态机，也没有声称修复上表中的缺口。
- 仅凭离线测试不能证明六个任务的内容质量或课程最终得分。
- 重启恢复只能保证已原子写入的状态；进程在外部副作用成功、状态保存前崩溃时，仍需先检查外部系统再决定是否重试。
- 上下文中的私信隔离是 Agent 可见范围控制；完整导出仍包含私信，只能提供给获授权的人类评估者。
