# 六项任务的试跑与验收清单

这些是帮助人工验收的建议，不是官方隐藏评分标准。要求团队在运行时自主确认范围与技术方案，不预设人类答案。每个场景都在同一群组依次运行任务 1、任务 2；三个场景的群组隔离。先做开发试跑，再用新群组做正式记录。

## 软件团队：预约系统

- 明确时区、使用者、房间数据和部署方式，记录真实回答或经认可的假设。
- 可以实际查看可用房间、预约、取消；数据重启后仍存在。
- 同房间重叠预约拒绝；不同房间不误阻止；结束时间等于下次开始时间的边界明确。
- 并发预约不产生双订；非法/反向时间有可理解错误；取消后可重新预约。
- 提供全部可运行源码、启动命令、独立测试和使用说明，发布实际产物。
- 发布版本与 Git 记录真实；只在明确获批后推送。

## 软件团队：使用率看板

- 复用第一题真实持久化记录，不用硬编码图表假装实时统计。
- 日期范围可交互选择；统计各房间预约次数、预订时长、繁忙日/时段和取消率。
- 定义时间范围边界、跨日预约截断、取消记录处理、取消率分母；避免把取消删除得无迹可查。
- 使用已知输入数据独立核对计算；验证无数据、跨日/跨月和取消后更新。
- 图表与摘要在浏览器可用，支持重载，提供房间分配建议及限制。

## 新闻编辑部：校园 AI 新闻

- 先确定具体、近期、与 HKUST 学生和教职工相关的事件；研究证据支持“近期”。
- 优先访问学校/部门官方公告，再与独立来源交叉核对，标注事件时间和检索日期。
- 不虚构采访、引语、联系人、参与人数或政策内容。
- 交付适合不同渠道的版本，例如新闻正文、校园短讯、社交平台摘要，文件为 Markdown。
- 提供 claim→source 对照、事实核查意见及未确认事项。

## 新闻编辑部：AI 写作检测事实核查

- 明确“可靠”及“判断某一学生作业”的含义，不用检测器自述代替验证。
- 结合一手研究、评测方法、工具自身说明及高校政策，检查时间和适用范围。
- 区分误报率、漏报率、基准发生率、语言/学科差异、模型更新与文本改写影响。
- 结论与不确定性对应证据，不把概率分数当成学术不端证明。
- 适配学生和教师两类读者，给出合理处理建议及证据局限。

## 基金团队：模拟投资方案

- 基于用户真实回答明确投资期限、流动性需求、风险承受及其他资产；不替用户默认最大风险。
- 解释港币/美元换算假设、交易费用、税务不确定性、现金与再平衡；不执行真实交易。
- 权重合计与金额准确，与 HKD 1,000,000 总额一致，来源有日期。
- 风险经理独立检查集中度、相关性、汇率及下行情景，说明哪些风险没有足够数据量化。
- 给出可理解的方案和风险说明，不保证回报、不编造实时价格。

## 基金团队：半导体 HTML 幻灯片

- 如果实际数据尚未到 2026 年底，明确真实数据截止日，将年末/以后判断标为情景预测。
- 由团队自主确定范围；覆盖支持投资判断的产业链、供需、资本开支、竞争与政策风险。
- 投资影响、反证及风险和研究证据对应，不能仅汇总厂商宣传。
- 交付浏览器可直接打开的 HTML，支持逐页展示和键盘导航，含参考来源与日期。
- 尽量内置资源，避免演示时依赖不稳定 CDN；提供独立审查记录与 Markdown 使用说明。

## 实验记录

每个正式批次记录代码版本、模型、配置、任务顺序、初始记忆和人类交互。保存完整对话、失败和重试，不只保留成功截图。报告总体/子任务完成率、逐题耗时及人类等待；如重复实验，说明每次是否清空记忆。

当前没有六项任务的真实质量分数。接口探测与离线状态机测试不计入六项任务完成率。
